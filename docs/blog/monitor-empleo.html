Cómo construí un monitor de empleo remoto con Python, Telegram y Discord

Vivir en Cuba y buscar trabajo remoto en el sector tecnológico es complicado. Las plataformas habituales (LinkedIn, Indeed) tienen acceso restringido desde aquí. Y las que funcionan suelen estar en inglés y con ofertas de nivel senior. Así que construí un sistema que busca ofertas en fuentes accesibles desde Cuba, las filtra por relevancia para mi perfil, y las envía a Discord sin repetir las ya vistas.

El problema

Quería buscar trabajo remoto, pero:

  • LinkedIn e Indeed están bloqueados o limitados desde Cuba.
  • Las plataformas que funcionan tienen mucho ruido: ofertas senior, ofertas que requieren presencia física, ofertas que no son de desarrollo.
  • Revisar manualmente cada día es tedioso y me olvido de hacerlo.

La solución: un sistema que lo haga por mí, todos los días, sin intervención.

Las fuentes

Después de investigar, elegí dos fuentes:

Remotive

Es una plataforma de empleo remoto con una API pública y gratuita. Devuelve ofertas de empresas de todo el mundo, muchas de ellas aceptan candidatos de cualquier país. Es accesible desde Cuba sin problemas.

Telegram: CubanTech Jobs

Es un grupo de Telegram donde se publican ofertas de empleo para cubanos del sector tecnológico. No tiene API oficial, pero con la librería Telethon puedo leer los mensajes del grupo como si fuera un usuario normal.

La arquitectura

Dos workflows de GitHub Actions, uno para cada fuente:

  • remotive-jobs.yml: consulta la API de Remotive.
  • telegram-jobs.yml: lee los mensajes del grupo de Telegram.

Ambos corren una vez al día, filtran las ofertas, y envían a Discord solo las nuevas.

El filtrado

Aquí está la parte más importante. Sin filtrado, el sistema enviaría 50 ofertas al día, la mayoría irrelevantes. Con filtrado, envía 1 o 2 ofertas que de verdad me interesan.

El filtro tiene tres niveles:

Palabras clave fuertes

Si la oferta menciona alguna de estas palabras, es candidata:

  • android
  • kotlin
  • flutter

Son las tecnologías que domino o quiero dominar. Si la oferta las pide, es relevante.

Palabras clave débiles

Si la oferta menciona alguna de estas palabras Y menciona "remote", es candidata:

  • mobile
  • developer
  • engineer
  • programmer

Son palabras genéricas. Por sí solas no garantizan que sea relevante, pero si van acompañadas de "remote", vale la pena mirar.

Palabras de exclusión

Si la oferta menciona alguna de estas palabras, se descarta:

  • senior, lead, principal, 5+ years (nivel demasiado alto)
  • presencial (no es remoto)
  • sales, marketing, recruiter (no es desarrollo)
  • power bi, webflow, django, fullstack (fuera de mi stack)
  • data scientist, devops, qa (roles distintos)

La deduplicación

El sistema corre todos los días. Si no hiciera nada, cada día me enviaría las mismas ofertas. Por eso, cada oferta se hashea (con SHA-256) y se guarda en un Gist. Antes de enviar una oferta a Discord, se verifica si el hash ya está en el Gist. Si está, se ignora. Si no está, se envía y se guarda.

Esto permite que el sistema corra todos los días sin spamearme.

El envío a Discord

Cuando hay ofertas nuevas, se envían a Discord como un mensaje formateado. Cada oferta incluye:

  • Título del puesto.
  • Empresa.
  • Ubicación permitida.
  • Salario (si está disponible).
  • Enlace a la oferta original.

Si hay más de 5 ofertas, solo se envían las 5 más relevantes para no saturar el canal.

Lo que aprendí

Tres lecciones:

  1. El filtrado es más importante que la fuente. De nada sirve consultar 1000 ofertas si 990 son irrelevantes. Un buen filtro convierte 1000 ofertas en 5 útiles.
  2. La deduplicación es esencial. Sin ella, el sistema se vuelve inservible a los pocos días. Con ella, cada notificación es una oferta nueva que merece la pena mirar.
  3. Telethon es una herramienta muy potente. Permite leer mensajes de grupos de Telegram como si fueras un usuario normal. Es perfecto para automatizar este tipo de cosas sin depender de APIs oficiales que no existen.

Conclusión

Este sistema me ha permitido encontrar ofertas que de otra forma se me habrían escapado. No es perfecto: el filtrado deja pasar algunas ofertas irrelevantes y descarta algunas relevantes. Pero es mejor que revisar manualmente todos los días.

Si estás en una situación similar (buscar trabajo remoto desde un país con restricciones), mi recomendación es: empieza con una sola fuente, añade un filtro básico, y ve iterando. No intentes cubrir todas las plataformas desde el primer día.
